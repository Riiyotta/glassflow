# CHANGELOG

## 1.2.0 (2026-10-29), clone / generation modes + baseline R1-R14. Status: design-review-pending

Revision pass against an external punch list (GlassFlow review items 1-10) and the skill baseline audit, which
reported 7 pass / 14 fail before this pass and 21 pass / 0 fail after it. Every item was checked against the
repo first. Agent work throughout: no human reviewed the derived patterns, availability decisions, whitelist or
policy binding.

### Modes (R1, R2)
- PageSpec `mode: "clone" | "generation"` is required and closed; `pageSpecVersion` 1.1.0 -> 1.2.0. The existing
  example is `mode: "clone"` and still validates with real GlassFlow assets and copy (the clone control).
- Generation mode requires `spec.brand` (operator brand name, placeholder/user-supplied mark, 1-2 product slugs);
  clone mode forbids it.
- New semantic rules (also in compatibility/graph.json): GENERATION_MODE_BRAND / _PERSON / _CUSTOMER /
  _THIRD_PARTY / _SCREENSHOT / _ASSET / _URL / _EMBED / _CLAIM / _COPY, plus CONTRACT_INTEGRITY.
- `extraction/build_source_identity.py` derives the blocklist from src/, CLONE_SPEC.md, ASSETS.md, specs/*.md
  and public/assets into `policies/source-identity.json`: 7 brand terms, 34 people, 6 customers, 21 third-party
  marks, 23 hosts / 55 URL prefixes, 1 embed, 322 asset files, 47 numeric-claim fingerprints, 13,212 hashed
  5-word copy shingles. Each term carries file:line evidence. verify_all rebuilds it and fails on drift.
- Source-pinned content patterns ("Read the full ... on glassflow.ai", `https://www.glassflow.ai/`, the cal.com
  embed) now also accept reserved `.example` / `.invalid` hosts so a generated page can be valid; the
  generation rules reject the GlassFlow branch.
- The quickstart card `product` key (renders `glassflow-<key>`) accepts a brand slug; in generation mode it must
  be one of `spec.brand.products`.
- `chrome.navbar`, `chrome.footer`, `chrome.legacy-nav`, `conversion.two-products-band` hard-code GlassFlow
  content in the clone renderer. They now declare `generationSubstitution` (what is fixed, cited, and which
  `spec.brand` fields replace it). Renderer compliance is not machine-checked.

### Asset roles (R3)
- `generationPolicy` renamed `cloneModePolicy`; every role gains closed `availability`, `generationModePolicy`,
  `generationSafeSubstitutes`, `generatedModeGuidance`, `kind`.
- blocked-for-generation: logo.third-party, logo.customer, brand.glassflow-mark, brand.dither-mark,
  person.real-photo, product.screenshot. clone-only: scene.mars-figurative, blog.cover, animation.lottie.
- New generation-safe roles: brand.placeholder-mark, asset.user-supplied, illustration.generated,
  screenshot.placeholder, person.fictional-avatar, logo.placeholder-company (media) and url.placeholder,
  copy.original (content policies).
- Every section media field that accepts a source role now also accepts its substitutes + asset.user-supplied;
  contracts list `generatedAssetRoles`. Ref pattern allows `placeholder:<id>` / `user-supplied:<id>`.
- `PINNED_AVAILABILITY` in verify_all.py and semantic_validate.py; the two tables and the registry must agree.

### Generation examples (R4)
- `schema/examples/generated.<family>.pagespec.json`, one per template family (new `templateFamily` on every
  template; 11 families). Fictional brand "Northwind Relay", fictional people/companies, generated or
  placeholder media, `.example` URLs. They were scaffolded by an agent script from the section contracts using a
  hand-written fictional phrase bank (the script is not shipped), then validated by the real validator.

### Tokens (R10)
- `tokens/llm/token-catalog.json` is now generated from the real token files (`extraction/build_token_catalog.py`;
  it previously covered 4 groups and nothing checked it). verify_all `token-catalog-in-sync` fails on drift.
- `tokens/llm/token-policy.json` rewritten: slots, allowed names, rules. New optional node-level `tokens`
  object; `chrome.legacy-nav.linkTone` changed from raw hex (`#999999` / `#A8A3A3`) to the semantic names
  `text.link` / `text.link-category`. Rules TOKEN_UNKNOWN / _RAW_VALUE / _ARBITRARY_SPACING / _UNSUPPORTED_FONT /
  _THEME_MISMATCH. The clone has no per-instance override, so renderer support for `node.tokens` is not evidenced.

### Contracts (R7, R8)
- Every section has closed `source` {id, tag, file, lines} and `semantic` {id, category}, generated by
  `extraction/build_contract_provenance.py` from its implementedBy citations; verify_all re-reads every range
  and finds the tag. `schema/section-contract.schema.json` closes the contract shape.
- `retrievalEligible` on all 68 contracts; false (with reason) for layout.spacer and contact.success-panel; pinned
  in both validators with a runtime-UI name check. The clone has no cookie banner, modal, drawer or preloader
  section (grep found none; the legacy mobile menu and products dropdown live inside the chrome sections).

### Wrapper gate (R9, R6)
- `extraction/wrapper_gate.py` (thresholds in code), wired into verify_all. Heights measured at 1440px from the
  built clone for all 17 templates (25 routes) by `extraction/measure_sections.mjs` +
  `extraction/record_section_heights.py`. One hit, whitelisted: blog.post-grid = 91.5% of /blog (agent
  attestation, not a human sign-off). legal.toc-document (~78-80% of the two legal pages) is kept as one section:
  see README "R6 judgement call".

### Routes, policy, hygiene
- route-source-drift now also derives the live category pages from Category.jsx META and fails on any mapped path
  the router does not serve. All 160 routes (133 pages, 27 redirects) reconcile; the `*` Pending fallback is not
  a served page.
- `registry.manifest.json` `category: "saas"`, `designPolicy` -> `n0-saas-design-constraints-common` 0.1.0,
  commonIrVersion 0.5, hard-and-soft, with a computed contentHash; evidence in `policy/design-policy.json`.
- The manifest's "source project is not a git repository" note was stale (it is one; design-repo.zip is in
  .gitignore and not tracked). no-absolute-paths now also checks private-temp, tmp and Windows user-profile paths.
- prove_drift accepts `--scratch DIR`; 22 -> 45 drift cases. verify_all 19 -> 30 checks. Adversarial 18 controls /
  49 mutations -> 46 controls / 119 mutations.
- allowlistVersion 1.0.0 -> 1.1.0 (assetRoles, settableNodeProperties += tokens, settableTopLevelProperties).

### Limits (unchanged by this pass)
- Detection is string-based (normalised whole-word / substring / 5-word shingle). Paraphrase, translation and
  lookalike imagery are not detected.
- Visual parity clone vs live was not measured in this pass.

## 1.1.0 (2026-10-13), source refresh. Status: design-review-pending

Two pixel-audit fix passes changed 19 source files after 1.0.0 (list in extraction/measured-values.json `sourceChangesSinceV1_0`), and
79 citations broke. Every affected fact was re-derived from the current source rather than re-pointed. Unless stated otherwise, each change below is a SOURCE change, not a 1.0.0 contract error. tailwind.config.js, index.css and the assets did not change.

### Contract changes (what changed, not just line numbers)
- **layout.spacer**: two new variants. `divider-30-tablet-up` is the /rius under-nav divider, hidden below 810. `band-70` is the 72px band before the /rius/pricing calculator banner. `top-64` is now documented as desktop-only. Templates updated: product-rius starts `navbar, divider-30-tablet-up`; pricing has `add-ons, band-70, calculator-banner`.
- **pricing.comparison-table** (breaking): the component was rewritten as flex row groups.
  - Plans are now objects `{name, price, cta, highlight, icon}`, since each header cell carries a text-roll CTA.
  - Rows are `{label, values}` OR `{band}` (e.g. SUPPORT).
  - Motion: `text-roll`.
  - Responsive widths: label 160/200/200, plans 140/160/278, value padding 32/40/12.
- **pricing.add-ons**: max items 4 -> 8. The source has 7 add-ons; 1.0.0's limit of 4 was wrong even then. Tablet: 4-column grid, 642px tall, title panel 184px.
- **pricing.every-plan**: one grid filled row by row (interleaved), 1 -> 2 columns from 810.
- **hero.pricing**: H1 is 48/48 at every width. The 1.0.0 source set 32 on mobile. Padding is 32/40/64 and the image 400/671/full.
- **Tablet (810-1199) tier re-derived**:
  - benefits strip: 2 columns
  - logo groups: 2 columns
  - image-card grid: 2 columns (/tares), 3 (/rius)
  - retrospective: text first, then a 600px image; Lottie 562x281
  - agents table: 3 columns with equal Mid/Long rows; the phone column heads are replaced by a 262px cell
  - what-you-get: 2 columns, equal rows, 13px text
  - plan cards: 2x2
  - cta-xs: a row with 64px padding
  - Rius blog row: STACKED at tablet with 426px images, a row only at 1200
  - tabs image: 500px, inset 64
  - product hero image: 672px
  - calculator banner: 610px tall, text max 420
- **hero.product**: the image fills its cell (no 12px inset). The button row never wraps; at 390 the second button runs past the edge, recorded as a known-intentional quirk.
- **feature.timeline**: no 24px left inset below 1200.
- **conversion.image-cta / two-products-band**: copy-to-buttons gap is 32 on phone and 64 from tablet. The body is capped at 420 for pages/posts/cases (the 1.0.0 source used 640 for pages).
- **social-proof.testimonial `compact`** (/rius) is compact + bleed: quote 21/26/32, full-bleed at tablet.
- **hero.home**: on phones the hairline between the two stacked panels is removed.
- **Alternatives (all 12 alt.* sections)**: fixed, centred, clipped frame 420 / 918 / 1200 (arize) or 1234 (langfuse), typeset in font-display, not Inter.
- **tool.build-vs-buy-calculator**: no top band below 1200, gutters 16/64/64, root in the system font. Number formatting, table brand/subtitle fields and the short labels are code-owned, outside the content contract.
- **contact.signal-form**: panel padding 32/40/64, form frame 0/24/40, panel 564 tall. The calendar iframe is 552 tall.
- **contact.success-panel**: the image is hidden below 1200; panel padding is 64 everywhere.
- **case.studies-title**: padding is 32, or 64x32 from tablet.
- **case.study-cards**: stacked until 1200 (the 1.0.0 source had 2 columns from 810).
- **case.detail-body**: Visit Website opens a new tab.
- **legacy.category-grid**: 3 columns from 810 (the 1.0.0 source had 2 at tablet). The grid is padded 34/48 with 24px sides, and card images use a 385/220 aspect.
- **legacy.bottom-cta**: copy starts 408px into the image box. The heading is capped at 720px with break-words, and its gradient is 0deg per line.
- **chrome.legacy-nav**: a 1x26 #3B3B3B rule, links 24px apart, and a static GitHub star widget that embeds GitHub's mark (third-party: reuse exactly).
- **chrome.navbar**: the products cell is a focusable dropdown trigger (`span tabIndex=0 aria-haspopup`), not a link.

### Token changes
- **Colour**:
  - legacy `divider` #333333 is now attributed to the Category outline-button border.
  - new `nav-rule` #3B3B3B.
  - new `cta-heading-gradient` (0deg).

### Validator / tests

## 1.0.0 (2026-10-13), initial build. Status: design-review-pending

Built from scratch against the GlassFlow clone (src/ is ground truth; specs are a strong first draft).

### Built
- Tokens: foundation (colour incl. a separate legacy-black group, typography, radius, spacing, breakpoints, elevation, icon sizes, motion),
  semantic roles, component and layout tokens, two themes (`mars`, `legacy-black`), and the LLM layer (allowlist 1.0.0, catalog, policy).
- 18 primitives, 16 components, 68 section contracts (97 variants), 17 templates, 160 routes (108 sitemap; 27 redirects, 18 of them in the sitemap).
- Closed `assetRole` vocabulary (11 roles) with generation and licensing guidance; 9 roles are pinned.
- Policies: forms (endpoint pinned to `must-not-reuse-live-endpoint`), link kinds, long-form summary-only, known-intentional quirks.
- Compatibility graph: 20 rules with ids identical to `schema/semantic_validate.py`.
- Schema generated from the contracts (`schema/build_schema.py`), the home example, the semantic validator, the adversarial suite
  (18 controls, 46 mutations, each asserted against its expected rule), `extraction/verify_all.py` (19 checks) and `extraction/prove_drift.py`.

### Decisions
- `/tares` and `/rius` are separate templates: their node sequences differ (see templates.json).
- Arize and Langfuse share ONE `alternatives` template. `alt.install`, `alt.side-by-side` and `alt.better-pick` are optional, and `alt.split` is repeatable.
- Redirects are `routes.json` entries with kind=redirect, never templates.
- Spec-vs-src disagreements are recorded in `extraction/measured-values.json`; src was followed in every case.
- Source files that changed while this build ran (the concurrent motion pass) are listed in `extraction/measured-values.json`.concurrentChangesDuringBuild. Every motion citation was re-validated against the final source.

### Known gaps (recorded, not hidden)
- The /rius Lottie loop has no reduced-motion handling in src (`no-reduced-motion-handling`).
- Legacy nav link hover colour transitions have no motion-reduce class.
- Some dithered images are role-classified from manifest descriptions without visual inspection (marked INFERRED).
